# ArcGraph 0.3.0 changes and compatibility

ArcGraph is a local-first code semantic graph engine. 0.3.0 is beta software (PyPI classifier
`Development Status :: 4 - Beta`). It was published on PyPI on 2026-10-28; the two uploaded
files are byte-identical to the validated candidate built from commit
32a83c9ab63f8e753cbbf5991927f9194ce3acf8 (wheel sha256
`5c7c5590ff69e0e598b7a99b546a894b1a215d16b17f5242035b7c97d02b88be`, sdist sha256
`6e71bf8571cef07cb2d773dba048e1df27a20c9da3fe467054f57a0e7516456a`). Later commits on `main`
are not part of the uploaded files.
It contains everything in [0.2.1](v0.2.1.md) plus the changes below, made on `main` after the
commit the 0.2.1 files were built from (282eb8a89ecb063c573d40e32b65b794c32d1664). A version
label alone is not proof of package publication, platform support, or source/artifact identity.
Use `arcgraph version --json`.

## Upgrading

- The index storage version (1) and the read schema (1.4.0) are unchanged; an index built by
  0.2.1 still opens.
- Rebuild (`arcgraph build` or `arcgraph ops rebuild`) to get the changes below into an existing
  index: `table` nodes for module-level SQLAlchemy `Table(...)` declarations and their foreign-key
  edges, the new module ids for directories below a package that have no `__init__.py`, the
  removal of Next.js routes from Nuxt projects, and coverage contexts whose pytest id contains
  `::`.
- Module ids change for directories below a package without `__init__.py`: for example
  `mod:alembic.env` becomes `mod:mealie.alembic.env`, and `source_roots` in `arcgraph current`
  no longer lists such directories as roots. Callers that stored node ids from an earlier index
  must query them again.

## Queries

- **Behavior change.** `symbol NAME` with a bare name that a resource (table, queue, task, tool,
  logging sink, command, or environment configuration) shares with other definitions, including a
  bare module name, is now `ambiguous` and lists the candidates instead of resolving to the
  resource. Resources whose name equals the query are pinned at the front of the candidate list;
  the default candidate limit stays 8 and `candidates_truncated` reports omitted matches. Use the
  node id, such as `table:users`, to select the resource directly. Qualified resource names such
  as `pkg.tasks.add` and `celery:default` still resolve by exact qualified name.
- `symbol PATH` with an indexed file path stays `unresolved`, and `suggestions` now carries the
  module node id of that file; nothing is auto-selected. Use the module's dotted name or node id
  for `symbol`, or the file path with `context` or `impact`.
- A CLI `--max-results` above a command's ceiling now prints the requested value and the ceiling
  on stderr and adds an entry to `warnings` in the JSON output; the ceilings are unchanged (100
  for callers, callees, impact, context, explain, ci, report ci and report pr; 50 for similar;
  1000 for references). `arcgraph report ci` no longer fails with an internal error when run
  without `--require-precision`, `--require-coverage`, `--require-runtime-trace` or
  `--python-full` (0.2.1 left those options without defaults on that subcommand).

## Python frameworks

- **SQLAlchemy tables.** Module-level assignments, including annotated assignments, to
  `Table(...)` (also via `import sqlalchemy as sa` and `sqlalchemy.sql.schema`) produce `table`
  nodes with `declaration: "table"`; a literal `ForeignKey("table.column")` adds a `references`
  edge to the named table, and a referenced table without a declaration is an unresolved node
  without a source location. Table call shapes the adapter does not recognise, and non-literal
  table names, are skipped with an `adapter_quality_warning` diagnostic. These foreign-key edges
  are framework facts: `references` queries do not count them as precise-reference evidence, and
  the `backend` field is unchanged.
- **Migration snapshots.** Table declarations below a migration directory's `versions/` (a
  directory that also has `alembic.ini` or `env.py`, or an `alembic/versions` path segment) are
  not indexed as tables, so a historical schema snapshot can no longer replace the source model's
  `table` node or add `maps_to` edges from migration classes. Other symbols in migration files
  are still indexed. On the mealie checkout used for verification: 56 → 68 tables, 24 new
  foreign-key `references` edges, and 9 table nodes whose `path` had pointed at a migration file
  point at `mealie/db/models` again.
- **Source roots.** Automatic source-root discovery keeps a directory below a Python package in
  that package's import tree even when it has no `__init__.py`: `pkg/scripts/run.py` below
  `pkg/__init__.py` is `pkg.scripts.run`. Test packages are treated the same way. On mealie this
  reduces `source_roots` from 5 to 2 and renames 66 module ids.

## TypeScript frameworks

- Next.js route and component analysis runs only when the nearest project has `next` in its
  dependencies or devDependencies or a `next.config.*` file; a `nuxt` dependency or
  `nuxt.config.*` skips it, while Vue component analysis still runs. Nuxt route recognition is not
  supported. A Nuxt project indexed by 0.2.1 had Next.js route nodes that did not exist (mealie:
  138 routes and 69 edges); they are gone after a rebuild, so a `route` query on such a project
  returns no result instead of a wrong one.

## MCP

- `arcgraph_preview_change_plan` declares the shape of its `targets` elements: `kind` (`symbol`,
  `path`, `route`, `resource` or `contract`) and `value` are required; `resolution_policy`
  (`must_resolve` by default, `allow_manual_review`, `informational`), `reason`, `requested_by`
  and `repo_id` are optional. **Behavior change.** An element with an unknown field is now
  rejected by the MCP SDK's argument validation instead of returning an ArcGraph change error
  payload; semantic errors still return that payload.
- `arcgraph_entrypoint_flow` accepts `entrypoint` (symbol or route id), or both `method` and
  `path`; when neither form is complete, the error names both forms and the parameters received.

## coverage.py test contexts

- The JSON report is parsed as a stream and the unread `functions` and `classes` sections are no
  longer kept in memory; a test context whose parametrize id contains `::` (for example an IPv6
  literal) now matches its test. The `evidence_manifest` content is unchanged.
- Cost of a report with test contexts, measured on mealie (3,936 contexts, a 2.65 GB JSON report)
  on the release code commit: 32.2 s and 1,636 MiB peak, against 54.7 s and 9,814 MiB with 0.2.1;
  without contexts 14.7 s and 770 MiB.

## Performance

- A full build is faster: the type-analysis context that depends only on the whole node set is
  built once and shared across files, and similarity profiles no longer deep-copy ASTs. Output is
  unchanged field by field. On mealie a full build takes 14.4–15.3 s against 16.6–17.1 s with
  0.2.1, three rounds each.
- The CLI starts faster: the MCP server, change-safety, semantic-core and provider subpackages are
  imported only by the commands that use them. Command output and `--help` text are unchanged.

## Known limitations

- As in 0.2.0 and 0.2.1, a runtime trace event that names its caller by qualified name rather than
  by node id, and whose caller is a pytest test, produces edges from the test case node
  (`test:…`), not from the test function: the function node's callees do not include those edges,
  and `symbol` with that qualified name is ambiguous between the two nodes. Traces written by
  `arcgraph trace run` carry node ids and attach to the test function.
- Under `--backend auto` or `scip`, `references` labels any remaining imported precise-reference
  evidence (pyright, SCIP protocol, OpenAPI operation) as backend `scip`; 0.3.0 only removes the
  SQLAlchemy foreign-key edges from that path.
- Two declarations of the same `table:NAME` in different modules keep one `path` (the node id
  does not carry the module); module-level `Table(...)` makes this more likely than before.

## Compatibility notes from 0.2.1

The compatibility notes in [0.2.1](v0.2.1.md) and [0.2.0](v0.2.0.md) still apply unless a
