# ArcGraph 0.2.1 changes and compatibility

ArcGraph is a local-first code semantic graph engine. 0.2.1 is the version declared on `main`;
it has not been published, and its publication status is kept in the
[release notes index](../../RELEASE_NOTES.md) only. It contains everything in
[0.2.0](v0.2.0.md) plus the changes below, made on `main` after the commit the 0.2.0 files were
built from (6f5cd85c40774990838dbf62b9ae7f80af0feb64). A version label alone is not proof of
package publication, platform support, or source/artifact identity. Use
`arcgraph version --json`.

## Upgrading

- The index storage version and the read and index schemas are unchanged; an index built by
  0.2.0 does not need a rebuild for that reason.
- An index built with coverage.py JSON that has test contexts holds only the aggregate coverage
  edges (see below). Rebuild it with `arcgraph build --coverage PATH` or
  `arcgraph ops rebuild --coverage PATH` to get the per-test edges.

## coverage.py test contexts

- **Fixed.** The [0.2.0 notes](v0.2.0.md) say `--coverage` accepts coverage.py JSON with test
  contexts. In 0.2.0 a real build did not use those contexts: a context naming a pytest test
  matched both the test function and the test case node the pytest adapter adds, was dropped as
  ambiguous, and only the aggregate coverage edges were imported, with no warning. A context now
  resolves to the pytest test case node, or to the single function or method of that name when
  there is no test case node, so coverage edges start at the test that ran the lines.
- **New warning.** Test contexts that match no indexed test raise
  `coverage_python_unmatched_contexts` with their number and up to five examples. Static
  contexts, such as the empty context or `production`, are not test contexts and do not warn.
- **Behavior change.** When a coverage.py report has test contexts and none of them matches an
  indexed test, coverage status is `partial` (`coverage=partial` in `arcgraph current`), and the
  `coverage_inputs` check of `arcgraph ci` reports `warn`, or `fail` with `--require-coverage`.
  A report in which some test contexts match stays `available` and carries the warning above.

## Precision tools installation

- The README installed scip with `go install github.com/scip-code/scip/cmd/scip@v0.7.1`, which
  cannot work: scip v0.7.1's `go.mod` has a replace directive, and Go refuses a versioned install
  of such a module. On macOS and Linux the README now downloads the official v0.7.1 release
  package and verifies its published checksum.
- On Windows, `scripts/install-arcgraph-precision-tools.ps1` builds `scip.exe` v0.7.1 from a clone
  of the v0.7.1 tag; Go and Git are required, as scip publishes no Windows binary. With
  `-InstallGoWithWinget` the script now finds Go in the same session after winget installs it,
  instead of stopping with "Go is required".
- `@sourcegraph/scip-python` 0.6.6 fails while loading on native Windows, so the Windows script
  no longer installs it; run `arcgraph precision scip-python` in WSL. `arcgraph doctor`, the
  missing-tool message of `arcgraph precision` and the built-in docs give the route for the
  platform they run on.
- `arcgraph docs quickstart` gives the PyPI install instead of a source checkout, which it keeps
  for maintainers.

## Known limitations

- As in 0.2.0, runtime trace edges whose caller is a pytest test start at the test case node, not
  at the test function: a query for the test function by qualified name is ambiguous, and the
  callees of the function node do not include those runtime edges.

## For contributors

- CI uses `actions/setup-node` 7.1.0 and `actions/upload-artifact` 7.0.2, still pinned to full
  commit SHAs.
