# ArcGraph 0.1.0rc10 changes and compatibility

ArcGraph is a local-first code semantic graph engine. 0.1.0rc10 was published
on PyPI on 2026-10-04 as an alpha developer-preview pre-release; the two
uploaded files are byte-identical to the validated candidate built from commit
bd9864250ea9f46815cf08ef426a1d5873dfce60 (wheel sha256
`41350d26f29f65d0364ca0b91441a1f8b6201e5f77b8fd6018b380e125138d18`, sdist sha256
`d61f7e132530b37eecfb620292069c1482a398e05759992a8d0244e1a275a54d`). Later
commits on `main` are not part of the uploaded files. It contains everything in
[0.1.0rc9](v0.1.0-rc9.md) plus the changes below; the compatibility notes after
them are carried over from 0.1.0rc9 and still apply. A version label alone is
not proof of package publication, platform support, or source/artifact
identity. Use `arcgraph version --json`.

## Changes since 0.1.0rc9

### Symlinks in the output directory

- **Behavior change.** If `change-safety/`, `pins/`, `builds/`, a build
  directory under `builds/`, or `current.json` inside the ArcGraph output
  directory is a symlink, ArcGraph now reports an error instead of following
  it. The output directory itself may still be a symlink.
- Change-safety records and pins are rejected as `CHANGE_STORE_CORRUPT` on
  every read and write, including a symlink loop; a link that leaves the store
  is still `OUTPUT_PATH_OUTSIDE_CONTAINMENT`. Before, reads and writes followed
  a link inside the store, a write through a linked record overwrote the
  link's target, and a linked store root passed the health check.
- Reading an index reports a linked `builds/`, build directory or
  `current.json` as a missing index; writing an index refuses a linked
  `builds/`; `arcgraph ops prune` refuses to prune when `current.json` is a
  link. Before, these followed the link.
- An unsafe build name in a pin is no longer reported as an escape from
  `builds/`.

### Encoding

- When Python's file-system encoding is not UTF-8 (on Linux, only when both
  locale coercion and UTF-8 mode are turned off under a C or POSIX locale),
  `arcgraph build` on a project with a non-ASCII path now stops with an error
  that names the path and the remedy (a UTF-8 locale or `PYTHONUTF8=1`), exit
  code 2. Before, the build crashed with `UnicodeEncodeError`. Such paths are
  still not indexed in that configuration.

### Known limits

- Symlinks are checked when a path is named; one created between that check
  and the read or write is not caught. Anyone able to do that can already
  rewrite the output directory.
- Other files at the output root, such as `write.lock`, are not checked.
- On Windows, a build directory reached through an 8.3 short name is treated
  as a symlink. Network (SMB/UNC) paths were not tested.
- The known limits listed for [0.1.0rc9](v0.1.0-rc9.md#known-limits) still
  apply.

## Interfaces

- Explicit `setup --client` prepares Claude Code, Codex, Cursor and Hermes MCP
  configuration or a Pi CLI skill. A prepared configuration does not prove
  client connection or model use. See [client setup](../client-setup.md).
- Read schema `1.4.0` adds scoped resource/queue relations to explain and explicit
  risk diagnostic inclusion scopes. Index schema remains `1.0.0`.
- MCP entrypoint flow has a 64 KiB JSON budget. Explain relation sections have a
  32 KiB budget per target; this is not a global explain/get_risk size limit.
  `max_depth=0` does not expand outgoing edges. Follow truncation metadata.
- Explain/context accept `summary`, `standard`, `detailed`; `full` is invalid.
  Detailed follows `max_results` subject to the server cap. Summary/standard
  have smaller context limits.
- `truncated_scope` means response omission; `analysis_truncated_scope` means
  incomplete traversal or analysis. Increasing display limits cannot repair
  missing analysis.
- CLI JSON failures emit an error envelope; expected errors exit 2 and internal
  defects exit 1. Human/raw modes retain their separate stdout contracts.

Local `arcgraph_help` is the discovery guide; optional
`arcgraph_record_trial_feedback` appends structured feedback only when enabled.
Use `--trial-summary` for a privacy-bounded metrics aggregate.

## Python analysis and upgrade

Rebuild existing indexes after upgrading. Changed-file refresh cannot add new
analysis facts to old indexes. Imported constructors and annotations retain
provider dependencies across re-exports, deletion and restoration. Conservative
refresh can approach a full rebuild; it is not a minimal dependency graph.

Nested functions, comprehension-local bindings, bounded inherited methods,
nullable containers and unique pytest fixture providers can retain type identity.
Unknown/mixed unions, ambiguous bindings and general dynamic dataflow remain
unresolved. Fixture provider chains and returns inside context managers remain
outside the bounded inference. TYPE_CHECKING imports provide annotation identity,
not runtime constructor bindings. Optional injected attributes are narrowed only
under the supported stable __init__ branch pattern.

Diagnostic classification does not create graph edges. No result proves all
runtime callers, all resource writes, test adequacy or program correctness.

## Language capabilities

Python is a native L3 semantic static frontend. TypeScript and JavaScript are native L3 semantic static frontends.
Other documented languages require validated external semantic extractor payloads;
this is not default live compiler-backed extraction. SCIP and OpenAPI are L2
inputs through `arcgraph build --scip-graph-index PATH` and
`arcgraph build --openapi-spec PATH`. No language is claimed as L4.
See [language support](../language-support.md).

## Earlier payload and index migrations

TypeScript/JavaScript now scans `.mts`, `.cts`, `.mjs`, and `.cjs`,
resolves NodeNext runtime extensions and extensionless runtime modules, models
static Express routes as `route` nodes, and emits bounded structural
`similar_to` edges. `BuildWarning.frontend_name` identifies warning provenance,
and target-scoped freshness lists share one global sample with explicit unique
and omitted counts.
Coexisting `.jsx`, `.tsx`, and `.js` files receive distinct variant module
identities instead of colliding with same-stem `.ts` sources; rebuilding
intentionally changes affected node IDs, so a repository carrying such a pair
needs a full build rather than an incremental reindex. A same-stem runtime file
is treated as compiler output only with compiler provenance about that file --
a sibling source map or an inline `sourceMappingURL` marker. A declaration
companion is deliberately not accepted: under `emitDeclarationOnly` it proves
the TypeScript source was compiled, not that the runtime file was emitted. A
hand-written shim therefore stays indexed and Change Safety keeps tracking it,
a `tsc` emit carrying neither signal is indexed as source, and skipped emit
artifacts are disclosed in one build warning with a count and sample paths.
Same-repository linked Git worktrees are excluded at any nested path using
Git's worktree registry, while submodules, nested clones, and vendored
repositories remain indexable.

Incremental TypeScript/JavaScript reindex is intentionally fail closed when it
cannot preserve Express mount context, module identities, similarity-profile
compatibility, or extractor availability; Python reindex also fails closed on a
legacy similarity generation instead of deleting it. It parses changed files
while reusing compressed persisted module identities and declaration context,
and rescoring only affected old/new similarity buckets, so static imports from a
changed file to an unchanged local module and deterministically resolved direct
`calls` remain available. Dynamic, ambiguous, or otherwise unmappable
relationships remain best-effort; run a full `arcgraph build` before relying on
complete import topology.

The earlier read schema `1.3.0` introduced bounded target-scoped payloads. MCP tool names
remain stable, but the payload contract is not byte compatible. In
`arcgraph_get_risk`, `blast_radius` entries are now stable-ID-only objects;
their previous `name`, `qualname`, `path`, `start_line`, and `end_line` fields
were removed to keep the default Change Preflight bounded. Follow the returned
recommended reads or query those IDs when full node detail is needed.
`arcgraph_find_similar` also intentionally changes its score and reason
contract: `token_jaccard=` replaces `token_overlap=`, and call/resource
agreement can only raise a structural score rather than disagreement vetoing a
pair. Consumers must negotiate this read schema; it is not byte/behavior compatible
with older payloads.
Read schema `1.3.0` also narrows `unknowns.kind=truncated_scope` to response
presentation and uses `analysis_truncated_scope` for incomplete traversal or
analysis data. Consumers matching only the old kind must recognize both values;
raising `max_results` resolves only the response kind. The upgrade of Change graph comparison projection to `1.2` removes location-derived embedded IDs while preserving their
semantic binding-shadow and type-inference relationships, so moving code alone
does not create a semantic delta and changing a relationship cannot disappear.

Unresolved Change Preflight target reports preserve bounded resolver suggestions
and include their paths in recommended reads. Stale warnings, machine-readable
recovery actions, Agent capability metadata, and Agent help consistently use
`arcgraph sync --if-stale` as the normal explicit recovery path. Assurance and
the `unknowns` list share one evidence-status interpretation, including
`precision_available`. Similarity pattern-family expansion uses indexed
source/target traversal of the target's connected component instead of scanning
all similarity edges and nodes on every preflight.

Default Change Preflight presentation uses the caller's `max_results`; there is
no second hidden sample cap. Every omitted section and unresolved diagnostic is
counted in `truncation`; when target scope is unresolved, numerous index
warnings are summarized by kind without claiming that any warning is unrelated.

Unresolved-call release triage now follows binding and resolution evidence.
Already-unresolved direct calls through a visible local or module runtime
binding carry bounded diagnostic evidence and classify as `true_dynamic_call`.
This classification does not create, suppress, or relabel graph edges; a
parameter that shadows a same-named module symbol remains local evidence.
Callback-like names and test-directory paths alone no longer lower an ordinary
unresolved call from `static_candidate`; explicit mock/assertion syntax remains
the bounded `mock_or_assertion` case.


See `arcgraph docs migration-notes` for the installed reference and
[release tooling](../release-tooling.md) for artifact verification.
